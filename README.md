## Features

- Buffered turns via `Thread.RunAsync`
- Real-time JSONL event streaming via `Thread.RunStreamedAsync`
- Resumable Codex threads with `StartThread` and `ResumeThread`
- Strongly typed event and item models for agent messages, command execution, file changes, MCP tool calls, web search, reasoning, and to-do lists
- Structured output through JSON Schema with `TurnOptions.OutputSchema`
- Local image input through `Input.FromParts`, `TextInput`, and `LocalImageInput`
- Codex CLI configuration for models, context windows, automatic compaction thresholds, sandboxing, approval policy, reasoning effort, web search, additional directories, base URL, API key, and environment variables
- Microsoft Agent Framework integration through `CodexSdk.MAF`
- Typed Codex app-server protocol access through `CodexSdk.AppServer`
- Microsoft Agent Framework integration backed by the app-server through `CodexSdk.AppServer.MAF`
- .NET 10.0 target with nullable reference types and implicit usings enabled

## Quick Start

### Buffered Turn

```csharp
using OpenAI.CodexSdk;
using CodexClient = OpenAI.CodexSdk.Codex;

var codex = new CodexClient();
var thread = codex.StartThread();

var turn = await thread.RunAsync("List the files in the current directory.");

Console.WriteLine(turn.FinalResponse);
Console.WriteLine($"Thread ID: {thread.Id}");
```

### Streaming Events

```csharp
using OpenAI.CodexSdk;
using CodexClient = OpenAI.CodexSdk.Codex;

var codex = new CodexClient();
var thread = codex.StartThread();

await foreach (var evt in thread.RunStreamedAsync("Summarize this repository."))
{
    switch (evt)
    {
        case ItemCompletedEvent { Item: AgentMessageItem msg }:
            Console.WriteLine($"[agent] {msg.Text}");
            break;

        case ItemCompletedEvent { Item: CommandExecutionItem cmd }:
            Console.WriteLine($"[cmd] {cmd.Command} exit={cmd.ExitCode}");
            Console.WriteLine(cmd.AggregatedOutput);
            break;

        case TurnCompletedEvent completed:
            Console.WriteLine($"[usage] in={completed.Usage.InputTokens} out={completed.Usage.OutputTokens}");
            break;
    }
}
```

### Structured Output

```csharp
using OpenAI.CodexSdk;
using CodexClient = OpenAI.CodexSdk.Codex;

var codex = new CodexClient();
var thread = codex.StartThread();

var schema = new Dictionary<string, object?>
{
    ["type"] = "object",
    ["properties"] = new Dictionary<string, object?>
    {
        ["summary"] = new Dictionary<string, object?> { ["type"] = "string" },
        ["status"] = new Dictionary<string, object?>
        {
            ["type"] = "string",
            ["enum"] = new[] { "ok", "action_required" },
        },
    },
    ["required"] = new[] { "summary", "status" },
    ["additionalProperties"] = false,
};

var turn = await thread.RunAsync(
    "Summarize the git status of the current repository.",
    new TurnOptions { OutputSchema = schema });

Console.WriteLine(turn.FinalResponse);
```

### Local Image Input and Resume

```csharp
using OpenAI.CodexSdk;
using CodexClient = OpenAI.CodexSdk.Codex;

var codex = new CodexClient();

var thread = codex.StartThread(new ThreadOptions
{
    SandboxMode = SandboxMode.ReadOnly,
});

var turn = await thread.RunAsync(Input.FromParts(
[
    new TextInput("Describe what you see in these screenshots."),
    new LocalImageInput("./ui.png"),
    new LocalImageInput("./diagram.jpg"),
]));

Console.WriteLine(turn.FinalResponse);

var savedThreadId = thread.Id ?? throw new InvalidOperationException("Thread ID was not set.");
var resumed = codex.ResumeThread(savedThreadId);
var followUp = await resumed.RunAsync("Continue the analysis from where we left off.");

Console.WriteLine(followUp.FinalResponse);
```

### Microsoft Agent Framework Integration

```csharp
using Microsoft.Agents.AI;
using OpenAI.CodexSdk.MAF;

var agent = new CodexAIAgent();
var session = await agent.CreateSessionAsync();

var response = await agent.RunAsync(
    "Explain what this project does in one paragraph.",
    session);

Console.WriteLine(response.Text);

await foreach (var update in agent.RunStreamingAsync(
    "List the files in the samples directory.",
    session))
{
    if (!string.IsNullOrWhiteSpace(update.Text))
    {
        Console.Write(update.Text);
    }
}
```

## Architecture

The SDK uses a thin process bridge over `codex exec --experimental-json`, then maps the JSONL event stream into .NET types.

### Core Components

**Codex** - Main SDK entry point

- Creates new threads with `StartThread`
- Resumes existing threads with `ResumeThread`
- Owns global `CodexOptions`
- Reuses the same Codex CLI execution bridge across threads

**Thread** - Conversation and turn API

- Runs buffered prompts with `RunAsync`
- Streams events with `RunStreamedAsync`
- Stores the current thread ID after `thread.started`
- Supports text, local image inputs, and per-turn structured output

**CodexExec** - Codex CLI subprocess bridge

- Resolves `CodexOptions.CodexPathOverride` or `codex` before each invocation using `PATH`, Windows `PATHEXT`, and a Unix login shell after a `PATH` miss
- Starts `codex exec --experimental-json`
- Sends prompts through stdin
- Yields stdout JSONL lines as an async stream
- Applies CLI arguments, config overrides, and environment variables

### Event Types

All streamed events derive from `ThreadEvent`:

- `ThreadStartedEvent` - contains the resumable thread ID
- `TurnStartedEvent` - emitted when a prompt starts processing
- `TurnCompletedEvent` - contains token usage
- `TurnFailedEvent` - contains terminal turn errors
- `ItemStartedEvent` - emitted when a thread item begins
- `ItemUpdatedEvent` - emitted as a thread item changes
- `ItemCompletedEvent` - emitted when an item reaches a terminal state
- `ThreadErrorEvent` - emitted for unrecoverable stream errors

### Item Types

All thread items derive from `ThreadItem`:

- `AgentMessageItem` - final or intermediate agent text
- `ReasoningItem` - reasoning summary text
- `CommandExecutionItem` - command, status, output, and exit code
- `FileChangeItem` - file patch changes and apply status
- `McpToolCallItem` - MCP server, tool, arguments, result, and errors
- `WebSearchItem` - web search query information
- `TodoListItem` - agent task list state
- `ErrorItem` - non-fatal item-level errors

## Microsoft Agent Framework Integration

The `CodexSdk.MAF` package provides a `Microsoft.Agents.AI` bridge backed by Codex threads.

### CodexAIAgent

- Implements `AIAgent`
- Supports buffered `RunAsync` and streaming `RunStreamingAsync`
- Converts Codex usage into `UsageDetails`
- Uses `ChatHistoryProvider` when configured
- Converts image `DataContent` inputs to temporary local image arguments for the duration of each turn
- Maps assistant responses to `ChatMessage` and `AgentResponseUpdate`

### CodexAgentSession

- Stores the Codex `ThreadId`
- Serializes and deserializes session state
- Enables conversation continuity across processes or requests

### CodexAIAgentOptions

- Accepts core `CodexOptions`
- Accepts per-thread `ThreadOptions`
- Supports explicit `ThreadId`
- Uses `IsResume` to resume an existing Codex thread selected by options
- Accepts an optional `ChatHistoryProvider`

## Codex App Server Integration

The `CodexSdk.AppServer` package starts `codex app-server`, completes the JSON-RPC handshake, and exposes typed protocol requests and notifications. Version 2 request and response models are in `OpenAI.CodexSdk.AppServer.Protocol`; `initialize` models are in `OpenAI.CodexSdk.AppServer.Protocol.V1`.

```csharp
using OpenAI.CodexSdk.AppServer;
using OpenAI.CodexSdk.AppServer.Protocol;

await using var client = await CodexAppServerClient.StartAsync(new CodexAppServerClientOptions());
var thread = await client.ThreadStartAsync(new ThreadStartParams());
var completions = client.SubscribeTurnCompleted(thread.Thread.Id);

var turn = await client.TurnStartAsync(new TurnStartParams
{
    ThreadId = thread.Thread.Id,
    Input = [new TextUserInput { Text = "Explain what this repository does in one paragraph." }],
});

await foreach (var notification in completions)
{
    if (notification.Parameters.Turn.Id != turn.Turn.Id)
    {
        continue;
    }

    if (notification.Parameters.Turn.Status == TurnStatus.Failed)
    {
        var error = notification.Parameters.Turn.Error.GetValueOrDefault();
        throw new InvalidOperationException(error?.Message ?? "The Codex app-server turn failed.");
    }

    Console.WriteLine($"Completed turn: {notification.Parameters.Turn.Id}");
    break;
}
```

The `CodexSdk.AppServer.MAF` package provides the `CodexAppServerAIAgent` Microsoft Agent Framework integration. It uses a connected app-server client and can keep conversation state in a session:

`CodexAppServerAIAgentOptions.OnResponseUpdateAsync` is awaited before each converted update is accumulated or delivered, allowing an application to complete its persistence work before exposing output. `ConfigureThreadResume` applies current provider, working-directory, and other typed overrides when a serialized session is resumed; the SDK preserves the session's thread ID and rejects replacement history or paths. The application continues to own and dispose the connected client.

```csharp
using OpenAI.CodexSdk.AppServer;
using OpenAI.CodexSdk.AppServer.MAF;

await using var client = await CodexAppServerClient.StartAsync(new CodexAppServerClientOptions());
var agent = new CodexAppServerAIAgent(client);
var session = await agent.CreateSessionAsync();
var response = await agent.RunAsync("Explain what this repository does in one paragraph.", session);

Console.WriteLine(response.Text);
```

When the Codex CLI executable is not available on `PATH`, set `CodexAppServerClientOptions.ExecutablePath` to its executable path:

```csharp
var options = new CodexAppServerClientOptions { ExecutablePath = "/path/to/codex" };
await using var client = await CodexAppServerClient.StartAsync(options);
```

See [the AppServer samples](samples/AppServerSamples) for runnable examples of typed protocol calls, command approvals, MAF session serialization and resumption, and image input.

The packages target .NET 10 and the pinned Codex 0.163.0 protocol: 172 client requests, 11 server request handlers, 85 public notifications, `initialized`, and the two raw-response notifications. Models and named client methods are compiled from the [official schema snapshots](src/CodexSdk.AppServer/Protocol/Schema). `Optional<T>` preserves field presence: `default` omits a field, `new Optional<string?>(null)` supplies JSON `null`, and a concrete value supplies that value. Protocol JSON can be read with `AppServerJson.Deserialize<T>` or serialized with `AppServerJson.CreateOptions()`.

Each `Subscribe...` call creates an independent notification stream and accepts thread/turn filters. Call it before sending the request whose notifications you need. `Register...Handler` methods accept typed asynchronous handlers for approvals, user input, dynamic tools, authentication refresh, and the other server requests. Unregistered handlers return an RPC error. Request cancellation cancels the local RPC wait; `TurnInterruptAsync` interrupts an active turn. The MAF adapter interrupts its owned turn when execution is canceled or conversion fails and rejects concurrent execution on the same session.

`StartAsync` owns its Codex process. `ConnectAsync(IJsonRpcMessageHandler, ...)` accepts an existing transport and owns the supplied handler; use `CodexAppServerClient.CreateTransportFormatter()` when constructing it to retain message bytes until typed deserialization completes. This entry point supports a future WebSocket message handler. The current package supplies the local stdio connection. Startup arguments, working directory, and handshake timeout are configured through `CodexAppServerClientOptions`.

### App-server images

The MAF adapter emits generated PNG images and viewed local images as byte-backed `DataContent` in `AgentResponseUpdate.Contents`. It reads each completed `imageView` immediately and determines the MIME type with MimeTypesMap. Inline MCP images and dynamic-tool image data URIs follow the same conversion. Remote image URLs remain `UriContent`. Tool images retain their tool metadata; `threadId`, `turnId`, `itemId`, available `callId`, and `contentIndex` are attached to the content. A tool item's ID also supplies MAF's required correlation ID when its protocol event has no separate call ID.

Image content includes `imageSource` (`imageGeneration`, `imageView`, `mcpTool`, `dynamicTool`, or `functionOutput`). Reasoning content includes `reasoningKind` (`summary` or `content`), because those two parts have independent content indexes. Preserve both the kind and the index when grouping reasoning updates.

```csharp
using Microsoft.Extensions.AI;

await foreach (var update in agent.RunStreamingAsync("Generate an image, then view it.", session))
{
    foreach (var image in update.Contents.OfType<DataContent>())
    {
        Console.WriteLine($"{image.MediaType}: {image.Data.Length} bytes");
    }
}
```

Streaming and buffered runs share the converter. Image bytes are retained in the returned content and in an optional `ChatHistoryProvider`. Duplicate completed events are ignored by event identity; distinct image-view items using the same path each capture their own bytes. Invalid Base64, missing files, unsupported image MIME types, and failed image generation report errors.

Session serialization preserves the thread ID and history-provider state. Restored runs continue to use standard image events. Historical `imageView` items provide a path; reading that path obtains its current bytes, so past file contents require a previously saved `DataContent` snapshot. Raw-response subscriptions are available on the core SDK. Enable experimental capabilities explicitly in the initialization options and the relevant request options; MAF image conversion uses the standard events.

## Configuration

### Environment Variables

The SDK forwards environment variables to the Codex CLI process.

- `CODEX_API_KEY` - API key used by the CLI. Set from `CodexOptions.ApiKey` when provided.
- `CODEX_INTERNAL_ORIGINATOR_OVERRIDE` - defaults to `codex_sdk_cs`; an existing value is preserved.

Each invocation copies `CodexOptions.Env` when provided, or inherits the current process environment otherwise. Command lookup and the CLI process use this environment. A supplied dictionary fully replaces the host environment and remains unchanged.

On Unix, when lookup finds Codex through the login shell specified by this environment's `SHELL`, the CLI receives that shell's complete PATH. Relative entries are resolved against the shell's working directory. Other variables continue to come from the copied environment; SDK-provided API keys are applied after lookup.

### CodexOptions

Global options for the `Codex` client:

```csharp
using OpenAI.CodexSdk;
using CodexClient = OpenAI.CodexSdk.Codex;

var codex = new CodexClient(new CodexOptions
{
    CodexPathOverride = "/path/to/codex",
    BaseUrl = "https://api.openai.com/v1",
    ApiKey = "sk-...",
    Config = new Dictionary<string, CodexConfigValue>
    {
        ["model_provider"] = "openai",
        ["approval_policy"] = "on-request",
    },
    Env = new Dictionary<string, string>
    {
        ["CODEX_API_KEY"] = "sk-...",
    },
});
```

### ThreadOptions

Per-thread options forwarded to `codex exec`:

```csharp
var thread = codex.StartThread(new ThreadOptions
{
    Model = "gpt-5.6-sol",
    SandboxMode = SandboxMode.WorkspaceWrite,
    WorkingDirectory = "/path/to/project",
    SkipGitRepoCheck = true,
    ModelReasoningEffort = ModelReasoningEffort.High,
    ModelContextWindow = 1_000_000,
    ModelAutoCompactTokenLimit = 900_000,
    NetworkAccessEnabled = true,
    WebSearchMode = WebSearchMode.Live,
    ApprovalPolicy = ApprovalMode.OnRequest,
    AdditionalDirectories = ["/path/to/shared/context"],
});
```

`ModelContextWindow` and `ModelAutoCompactTokenLimit` are forwarded only when their values are greater than zero. Null, zero, and negative values are omitted. The Codex CLI may cap the effective context window based on the selected model's supported maximum.

### TurnOptions

Per-turn options:

```csharp
using var cts = new CancellationTokenSource(TimeSpan.FromMinutes(2));

var turn = await thread.RunAsync(
    "Return a JSON summary of this repository.",
    new TurnOptions
    {
        OutputSchema = schema,
        CancellationToken = cts.Token,
    });
```

## Key Behaviors

### Message Streaming and Termination

- `RunStreamedAsync` yields each parsed Codex JSONL event.
- `RunAsync` buffers completed items and returns a `Turn`.
- `RunAsync` stores the latest `AgentMessageItem.Text` as `Turn.FinalResponse`.
- `RunAsync` throws an `InvalidOperationException` when a `TurnFailedEvent` is received.

### Thread Resumption

- `Thread.Id` is populated from the `ThreadStartedEvent`.
- `Codex.ResumeThread(id)` resumes a thread persisted by the Codex CLI.
- MAF sessions serialize the Codex thread ID through `CodexAgentSession`.

### JSON Serialization

- Polymorphic event and item models use the `type` discriminator emitted by the CLI.
- Enum values are parsed from snake_case JSON names.
- Structured output schemas are written to a temporary JSON file and passed to `codex exec --output-schema`.

### Resource Management

- Each turn starts a Codex CLI subprocess and closes stdin after sending the prompt.
- Cancellation tokens terminate the underlying process when cancellation is requested.
- The SDK captures stderr and includes it when the CLI exits with a non-zero code.

## Troubleshooting

### Codex CLI discovery

Install the Codex CLI globally:

```bash
npm install -g @openai/codex
```

Before each invocation, the SDK resolves `CodexPathOverride`, or `codex` when it is omitted. Command names are searched using the invocation's environment snapshot; Windows uses `PATHEXT`, and Unix checks execute permission. After a Unix `PATH` miss, the SDK can read the `PATH` from a supported login shell named by that environment's `SHELL`, with a three-second timeout. A successful login-shell lookup also supplies the CLI process's PATH. Lookup honors cancellation. A lookup failure reports the requested command or path and any login-shell diagnostic.

If the CLI is installed in a custom location, pass the executable path:

```csharp
var codex = new Codex(new CodexOptions
{
    CodexPathOverride = "/path/to/codex",
});
```

When binding `CodexOptions` from JSON through a host integration (for example, an agw `Extra` block), provide `codexOptions` as a nested object:

```json
{ "codexOptions": { "codexPathOverride": "/opt/homebrew/bin/codex" } }
```

### "env: node: No such file or directory"

The npm build of the Codex CLI is a Node.js script (`#!/usr/bin/env node`), so its process PATH must contain Node.js. When the SDK discovers Codex through a login shell, it passes that shell's PATH to the CLI. The shell configuration must make both Codex and Node.js available, including installations in separate directories.

An explicit `CodexPathOverride` selects the executable directly. Its interpreter dependencies use the supplied or inherited environment, so that environment's PATH must include Node.js.

### Authentication Errors

Set your API key:

```bash
# macOS/Linux
export CODEX_API_KEY="your-api-key"

# Windows PowerShell
$env:CODEX_API_KEY="your-api-key"

# Windows Command Prompt
set CODEX_API_KEY=your-api-key
```

Or pass it via options:

```csharp
var codex = new Codex(new CodexOptions
{
    ApiKey = "your-api-key",
});
```

### Git Repository Check

If you intentionally run Codex outside a Git repository, enable:

```csharp
var thread = codex.StartThread(new ThreadOptions
{
    SkipGitRepoCheck = true,
});
```

### Sandbox and Approval Issues

Adjust the thread policy:

```csharp
var thread = codex.StartThread(new ThreadOptions
{
    SandboxMode = SandboxMode.WorkspaceWrite,
    ApprovalPolicy = ApprovalMode.OnRequest,
    NetworkAccessEnabled = true,
});
```
